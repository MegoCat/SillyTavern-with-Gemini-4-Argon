# 切到后台时使用画中画

切换标签页或应用时，酒馆会向浏览器申请画中画。小窗显示酒馆图标。切回酒馆时，网页会保留小窗，方便下次切换应用。用小窗上的关闭按钮即可收起，也可以在 **用户设置 → 杂项** 关闭“切到后台时自动打开画中画”。

在桌面 Chromium 实测，点击网页后立即切换标签页可以自动打开小窗。距离上次点击较久时，纯文字聊天可能不满足浏览器的自动画中画条件。遇到这种情况，可在切换前点击 **用户设置 → 杂项 → 立即打开画中画**，看到小窗后再切换应用。[Chrome 自动画中画说明](https://developer.chrome.com/blog/automatic-picture-in-picture-media-playback)

“用户设置 → 杂项”始终显示画中画开关和按钮。若控件为灰色，可在其下方查看原因。使用手机访问另一台设备上的酒馆时，可通过 HTTPS 访问。酒馆运行在手机本机时，也可以使用 localhost。

生成使用原网页的连接。请保持网页和网络连接开启。锁屏、系统回收浏览器进程或实际断网都可能中断生成。

## 在 Termux 查看耗时

Vertex Express 接到生成任务后会显示编号和模型。终端每秒原地刷新一行，编号右边是总耗时，阶段名右边是该阶段已用时间。遇到限流时，`429 x8` 表示累计收到 8 次 429，`retry in 4s` 表示距下次尝试还有 4 秒。多个任务并行时轮流显示，各自使用独立的编号和计时。

完成、失败或取消后，可以在终端查看总耗时和各阶段耗时。

- `prep` 从服务端开始处理生成到发出首次上游请求。
- `429` 包含被限流的请求往返和重试前的等待。
- `wait` 从最后一次发送请求到收到响应头。非流式模型常在生成结束时才返回响应头，这段时间也包含上游生成等待。
- 流式请求的 `first byte` 从收到响应头到收到第一块正文。`receive` 从第一块正文到服务端结束回复。非流式请求的 `receive` 从响应头开始，包含读取和处理完整回复的时间。

输出重定向到文件时只记录关键事件和最终汇总。

如果上游返回了元数据，耗时汇总下方会出现 `API metadata`。字段名和数值来自这次响应，例如模型版本、结束原因、各类 Token 用量和响应 ID。模型或代理添加的自定义字段也会显示。流式请求在结束时统一展示，重复上报的用量取最后一次的值。汇总会省略思考签名（`thoughtSignature`）、聊天正文和内嵌媒体数据。终端重定向到文件时，元数据使用单行 JSON。

## Android 回复通知

在运行酒馆的手机上安装与 Termux 来源相同的 **Termux:API** 应用，在 Termux 中运行 `pkg install termux-api`，并允许 Termux:API 显示通知。在酒馆的 **用户设置 → 杂项** 中开启 **Termux 回复通知**，之后发起的聊天生成会在回复就绪或最终失败时提醒一次。通知只显示结果状态。Vertex AI Express 在等待 429 重试时保持静默。
