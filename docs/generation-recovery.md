# Vertex AI 快速模式：断线后恢复最终回复

酒馆服务端接到请求后，即使手机断网、浏览器切到后台或页面关闭，也会继续生成。重新打开原聊天即可取回结果。首次请求声明函数时，默认将模型返回的第一个 `functionCall` 作为最终回复。

## 使用

更新 `release` 分支并重启酒馆服务端，然后刷新浏览器。内置扩展 **Generation recovery (Vertex Express)** 默认随其他内置扩展加载；未禁用扩展时无需新装依赖，也不需要修改 API 配置。

正常在线时可以逐字阅读。若生成途中断线，服务端继续生成，回到原聊天后自动补入最终回复。即使代理在半途中正常关闭了连接，前端也会等待服务端的结束标记，已经显示的半截文本仍可被完整结果替换。

切回原聊天、页面回到前台、恢复网络或浏览器恢复冻结页面时，都会触发检查。即使页面刚重开、没有本地任务记录，第一次查询遇到网络错误、429 或 5xx 也会自动重试。间隔从 2 秒逐步增加到 30 秒。页面隐藏时暂停定时检查，成功确认没有待办后停止轮询。

扩展设置里的 **断线恢复 / Generation recovery** 面板提供立即检查、停止后台生成、恢复到当前聊天、查看保存的正文和丢弃缓存。正常的“停止生成”按钮也会发送独立的服务端取消请求。手机离线时，浏览器先按酒馆账户和任务 ID 记录停止请求。即使随后关闭页面，下次用同一浏览器和账户打开酒馆时也会优先补发。服务端收到停止请求前，生成或 429 重试仍可能继续。

## 首次请求就要函数内容

在 **扩展设置 → 断线恢复 → 工具调用方式** 中，默认选中 **仅保存首个函数调用**。通过酒馆或扩展照常在第一条请求中声明函数。第一轮结束后，原聊天会显示一个 JSON 代码块，包含第一个 `functionCall` 的函数名、完整参数以及模型放在调用对象里的其他字段。嵌套对象、数组和空值都会保留。模型同轮给出多个调用时，按返回顺序取第一个。模型只回文字时，仍按普通回复显示。

这个模式在在线和断线时使用同一份服务端结果。即使手机在 429 重试期间或流式回复途中关闭网页，重新打开原聊天也只补入一次。流程到保存函数内容为止，工具插件不会执行，也不需要向模型发送 `functionResponse`。

旧版网页或扩展发送带函数声明的恢复请求时，可以省略工具模式。服务端照常提交请求，等第一轮完成后一次返回结果。若模型给出函数调用，就以 JSON 正文交付第一个调用，旧网页也能直接接收。

工具调用方式按酒馆账户保存。升级后，新请求默认采用上述模式。面板还提供以下选择。

- **执行工具并继续生成** 会在页面回到原聊天并使用原模型后，执行待处理工具并逐个保存结果，再请求后续回复。升级前已经进入执行流程的任务，可以切回该选项继续。原浏览器会在网络恢复后补交已暂存的工具结果。如果执行页面已关闭、结果未知，可选择 **跳过此工具并继续** 或 **停止工具任务**。静默工具仍遵循其原有的终止行为。
- **带工具的请求使用酒馆原流程** 让酒馆直接处理带工具的请求。这些请求依赖原浏览器连接。

## 在 Termux 查看耗时

Vertex Express 接到生成任务后会显示编号和模型。终端每秒原地刷新一行，编号右边是总耗时，阶段名右边是该阶段已用时间。遇到限流时，`429 x8` 表示累计收到 8 次 429，`retry in 4s` 表示距下次尝试还有 4 秒。多个任务并行时轮流显示，各自使用独立的编号和计时。

完成、失败或取消后，终端会留下总用时和分段明细：

- `prep` 从服务端开始处理生成到发出首次上游请求。
- `429` 包含被限流的请求往返和重试前的等待。
- `wait` 从最后一次发送请求到收到响应头。非流式模型常在生成结束时才返回响应头，这段时间也包含上游生成等待。
- 流式请求的 `first byte` 从收到响应头到收到第一块正文。`receive` 从第一块正文到服务端结束回复。非流式请求的 `receive` 从响应头开始，包含读取和处理完整回复的时间。

支持断线恢复的任务会在手机网页离线后继续计时。输出重定向到文件时只记录关键事件和最终汇总。

如果上游返回了元数据，耗时汇总下方会出现 `API metadata`。字段名和数值来自这次响应，例如模型版本、结束原因、各类 Token 用量、响应 ID 和完整的 `thoughtSignature`。模型或代理添加的自定义字段也会显示。流式请求在结束时统一展示，重复上报的用量取最后一次的值，早先收到的签名也会保留。聊天正文和内嵌媒体数据省略，终端重定向到文件时元数据使用单行 JSON。

## 当前范围

- Vertex AI **Express / 快速模式**的单角色文本聊天；支持普通回复、重新生成、续写和 swipe 重抽。
- 同时支持上游流式与非流式请求；保留正文、返回的思考文本和不透明的 `thoughtSignature`。
- 其他供应商、Vertex 服务账户模式、群聊、quiet/impersonate 和模型直接生成图片仍使用原流程。
- 服务端独立完成已经提交的模型请求。仅在选择 **执行工具并继续生成** 时，浏览器才需要为待恢复的请求运行工具插件。
- 浏览器尚未把请求送达服务端便被关闭时，没有后台任务可以恢复。

## 数据与冲突处理

任务记录保存在当前酒馆用户的数据目录下的 `generation-tasks/`。完成结果使用私有文件原子写入；原始提示词请求、请求头和 API 密钥不写入任务记录。续写和 swipe 的恢复上下文包含原助手消息；模型回复本身同样属于聊天隐私数据，应像聊天文件一样保护服务器和备份。

前端正常保存成功后，服务端检查原聊天文件中的任务完成标记，才清理对应结果。恢复写入校验聊天文件、历史指纹和消息标记，使用短期恢复锁防止多个标签页同时补入同一条消息。操作前在 `backups/recovery-<任务ID>.jsonl` 留下原聊天备份。

恢复时，服务端返回已写入的消息，前端只更新这一条，长聊天通常无需重新下载和渲染整段历史。若消息已经写入，但手机漏收了写入成功的响应，前端会按任务 ID 核对聊天文件并补上显示。等待期间你若编辑了原聊天，前端会保留编辑现场。

聊天被改名、删除，或者消息在生成后被修改、追加而无法安全匹配时，不自动覆盖；结果仍保留，可从面板查看正文。并发编辑仍应遵守酒馆原有的聊天保存约束，不建议多个标签页同时编辑同一聊天。

未确认的完成结果默认保留 24 小时，过期内容在访问任务列表或创建任务时清理。每用户同时最多 4 个后台生成、64 条未处理记录。单条任务的原始响应和工具结果合计最多 16 MiB，累计结果与运行任务预留空间最多 128 MiB；整个进程最多 16 个运行任务。确认后的任务保留有限去重标记。备份由现有备份目录管理，不随任务结果自动删除。

**服务端进程重启不是浏览器断线。** 已经完整落盘的结果可恢复；重启时仍在运行的请求标记为 `interrupted`，不会偷偷重试付费生成。现有 Vertex Express 429 的 5–10 秒随机重试逻辑不改动；浏览器离线后仍会继续重试，必须通过停止操作取消。

## 实现边界

服务器只在原受认证和 CSRF 保护的 chat-completions 路由前增加恢复包装层；未携带恢复上下文的生成保持原路径。包装层将原 Vertex 处理器连接到独立可写响应，浏览器只是可脱离的订阅者。缓慢或断开的浏览器不能阻塞上游；最终结果落盘后才进入可恢复状态。

新增的内置前端扩展使用已有生成事件附加任务上下文、标记消息、确认保存、发出取消请求和查询最终结果，没有替换全局 `fetch`。

无需访问任何模型 API 的测试：

```sh
node --test tests/generation-recovery.test.mjs
```

覆盖回复与 SSE 解析、UTF-8 分片、签名保留、断线后的继续生成、主动停止、重复请求去重、磁盘保存确认、聊天冲突、用户隔离、额度边界、慢客户端、短期恢复锁和服务端重启。前端回归用例还覆盖首次查询失败、同时收到多个唤醒事件、跨页面补发停止、确认响应丢失和等待期间编辑聊天。工具用例覆盖并行领取、回执丢失、结果未知、静默工具、调用签名以及后续模型请求去重。上述命令中的路由测试使用模拟路由注册器和原生 Node 流。

首个函数调用的测试覆盖流式与非流式回复、关闭并重开聊天、同时返回多个调用和原页面迟到。启动测试用酒馆实例后，在 `tests/` 下运行 `npm run test:e2e -- GenerationRecoveryStream` 可验证流结束标记，以及聊天代码块中 Markdown、HTML 实体和宏字符的显示与复制。

另外已用桌面 Chromium、实际酒馆服务端和本地模拟 Vertex 上游验证关闭重开、查询接口连续返回 503、流式连接提前结束、恢复确认丢失，以及离线停止后重开页面。实机 Android Chrome 和真实 Vertex 账户仍需在部署环境验证。
